## 2. Schema delta

Migration mới: [2026_11_01_014629_add_version_and_terminal_replay_to_program_sessions.php](../../backend/database/migrations/2026_11_01_014629_add_version_and_terminal_replay_to_program_sessions.php).

| Thành phần | Thay đổi | Ý nghĩa |
|---|---|---|
| `program_sessions.version` | Integer NOT NULL, default `1` | Version riêng của Session, tách khỏi `program_version` lịch sử |
| `program_sessions_version_check` | PostgreSQL `CHECK (version >= 1)` | Chặn version bằng 0 hoặc âm tại database |
| `program_sessions.terminal_replay` | JSONB nullable | Chuẩn bị nơi lưu actor/action/payload/kết quả của lệnh terminal theo K04.1 |
| `program_sessions.status` | Default đổi từ `planned` thành `scheduled` | Khớp vocabulary và status constraint hiện hành |

Phần tái sử dụng, không tạo lại:

- FK `lesson_sessions.program_session_id` tham chiếu `program_sessions.id`, kèm UNIQUE và restrict-on-delete, đã có trong [migration tạo bảng](../../backend/database/migrations/2026_10_07_000400_create_program_and_learning_tables.php).
- Status constraint PostgreSQL của planned/actual chỉ nhận `scheduled`, `completed`, `cancelled`, đã được điều chỉnh trong [migration đồng bộ domain](../../backend/database/migrations/2026_10_22_000000_align_program_schema_with_domain_design.php).
- Bảng `idempotency_receipts` dùng chung đã có; task này không thêm bảng receipt mới.

Migration mới không tạo actual, không tự complete/cancel, không thay đổi nội dung lịch hiện có. `down()` từ chối rollback tự động để tránh xóa version và lịch sử replay; muốn đảo migration phải có reverse migration được review.

## 3. Model và quan hệ

| File | Nội dung |
|---|---|
| [Program.php](../../backend/app/Models/Program.php) | Bổ sung `sessions(): HasMany` |
| [ProgramSession.php](../../backend/app/Models/ProgramSession.php) | `program(): BelongsTo`, `actual(): HasOne`; casts số nguyên/thời gian/metadata; ẩn `terminal_replay` |
| [LessonSession.php](../../backend/app/Models/LessonSession.php) | `plannedSession(): BelongsTo`; casts actual times; ẩn hai cột attendance legacy |

`ProgramSession` chỉ cho mass assignment các trường nội dung lịch trong contract. Các trường server quản lý như Program ID, status, version và replay metadata không nằm trong `$fillable`. `LessonSession` chặn toàn bộ mass assignment; writer phải gán dữ liệu server đã kiểm soát một cách tường minh.

Quan hệ `hasOne` hỗ trợ đọc dữ liệu; UNIQUE tại database mới là cơ chế chặn actual thứ hai cho cùng planned Session. Khai báo quan hệ không thay thế Policy.

Phạm vi bằng chứng:

| Tiêu chí | Test/bằng chứng |
|---|---|

## 6. Dữ liệu cũ và giới hạn replay

- Khi áp dụng migration, các planned Session cũ nhận `version=1`; `terminal_replay` ban đầu là NULL.
- Không tự suy actor, payload, expected version ban đầu hoặc response cũ để tạo metadata giả cho Session đã completed/cancelled.
- Session terminal cũ thiếu dữ liệu tái dựng replay phải được đối soát trước khi khẳng định hỗ trợ replay tương đương sau thời hạn receipt. Không chỉ dựa vào trạng thái cuối để nhận diện replay.
- Lượt kiểm chứng này không thống kê số lượng Session terminal cũ hay xác nhận đã backfill metadata trên từng database. Đây là giới hạn dữ liệu cần ghi nhận, không phải bằng chứng replay đã chạy.
- Test metadata chỉ chứng minh khả năng lưu/đọc JSON và ẩn dữ liệu; chưa chứng minh kiểm identity/scope/quyền, canonical payload, receipt retention hay response replay qua API.
- Migration được test khi dựng schema và đã có trạng thái Ran trên hai môi trường local. Chưa có diễn tập nâng cấp với bộ dữ liệu lịch sử production-like hoặc rollback dữ liệu.
