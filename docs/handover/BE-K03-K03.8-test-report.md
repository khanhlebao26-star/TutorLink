## 1. Hành vi và thay đổi

Conversation tiếp tục text-only. SendTextMessageRequest kiểm file_ids theo JSON gốc để phân biệt mảng rỗng [] với object rỗng {}, đồng thời kiểm input hiện hành cho request không phải JSON. Omission hoặc [] hợp lệ; null, scalar, object và mảng có phần tử trả 422 validation_failed với lỗi file_ids.

Client không gửi message_type=file/system hoặc trường upload file tùy ý. Request không hợp lệ không tạo Message/FileLink; multipart binary file cũng bị từ chối. Body/newline/UUID normalization và canonical hash hiện hành giữ nguyên, nên omission và [] vẫn replay cùng message.

FileUploadRequest tiếp tục không nhận purpose message_attachment. FileLinkRequest loại message khỏi resource_type và chỉ giữ một rule in; xóa rule cũ dư thừa có message. Controller vẫn chỉ thực hiện verification_document, các resource còn liệt kê nhưng chưa triển khai tiếp tục 409. Không sửa policy giấy tờ xác minh hoặc tự mở Task/Submission/CV.

Giữ Message::attachments(), enum/schema file/system/message_attachment, FileRecord và logic đối chiếu payload legacy. Không có migration hoặc backfill.

## 3. API/schema delta

| Request | Kết quả |
|---|---|
| POST Conversation messages: text, file_ids omitted hoặc [] | 201 khi mới, 200 khi replay hợp lệ |
| file_ids là {}, null, chuỗi, số, boolean hoặc mảng có phần tử | 422 validation_failed, errors.file_ids |
| message_type=file/system | 422 validation_failed |
| Multipart thêm binary file vào gửi text | 422; không tạo message/link/file record |
| POST /api/v1/files với purpose=message_attachment | 422 errors.purpose |
| POST /api/v1/files/{file}/links với resource_type=message | 422 errors.resource_type; trước đó controller từ chối 409 |
| Link verification_document hợp lệ | Giữ policy owner/file/profile/assignment hiện có |

OpenAPI được sinh từ code bằng Scramble. FileLinkRequest enum còn task, task_submission, announcement, verification_document; việc enum có các loại này không có nghĩa tất cả đã callable về nghiệp vụ: controller vẫn trả 409 cho các resource chưa hỗ trợ. Message resource DTO không bổ sung attachment/file URL. Giữ 69 operations, không thêm/bỏ route, không có schema delta. Rule PHPDoc mô tả rõ empty JSON array và message links disabled.

Inventory local trống nên không cần chuyển đổi dữ liệu. Môi trường khác phải kiểm kê riêng; không suy inventory local thành staging/production. Frontend hiện chỉ có upload avatar/giấy tờ ở Tutor onboarding; giữ các input này. Chưa có UI chat để kiểm nút upload hoặc chạy flow end-to-end. Khi frontend Messaging được xây, phải giữ text-only và bổ sung test UI tương ứng; source audit hiện tại không được dùng như bằng chứng UI chat đã nghiệm thu.

## 5. Known limitations và việc tiếp theo

- Không triển khai attachment DTO/download chat hoặc cấp thêm quyền tải legacy. Existing File policy giữ nguyên; outsider không tự có quyền chỉ vì biết ID.
- Generic File race link-vs-delete, orphan cleanup/storage compensation và resource policies Task/Submission/CV thuộc module phụ trách/M10/K03.10; không được đánh dấu đạt chỉ vì khóa chat thành công.
- Không có antivirus tự động; clean/complete không xác nhận đã quét malware. Giữ dữ liệu/evidence thật và policy 5.000.000 byte của K03.7a/K03.7b.
- Redocly còn 43 warnings. Một số File API dùng error envelope legacy; không tuyên bố mọi 422 đã dùng envelope Messaging.
- Frontend chat, Conversation lifecycle và realtime vẫn còn công việc; không đánh dấu toàn BE-K03 hoàn tất.

Tiếp theo: K03.9 đồng bộ Conversation lifecycle. Không có blocker kỹ thuật của phạm vi khóa attachment chat trong các kiểm tra đã chạy; chờ Hoàng review.
