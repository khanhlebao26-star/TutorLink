## 2. Chính sách chuyển tiếp

1. Giữ nguyên FileRecord và liên kết hồ sơ; không xóa, đổi owner hoặc reset hàng loạt các avatar đang tham chiếu.
2. Không backfill scan_engine/version/hash/time bằng giá trị giả. Không diễn giải cờ clean cũ hoặc kiểm checksum thành antivirus scan.
3. isComplete() tiếp tục biểu diễn lifecycle cũ cho các policy non-message. FileResource trả antivirus_scanned=false/scanned_at=null nếu chưa có bằng chứng hợp lệ. UI phải xét verdict cùng antivirus_scanned, không dùng complete=true làm nhãn đã quét.
4. Owner active gọi lại POST /api/v1/files/{file}/complete. Clean legacy không có evidence sẽ được đọc object, kiểm metadata và gọi scanner thật.
5. Clean hợp lệ lưu evidence cho hash hiện tại. Scanner/storage lỗi chuyển pending; malware/metadata vi phạm chuyển rejected. Khi đó không sử dụng được như một file complete.
6. Nếu cần thay avatar, dùng flow upload/complete/attachAvatar hiện hành; Profile approved có quy trình revision/review riêng. Không sửa avatar_file_id hoặc evidence bằng SQL.
7. K03.8 phải yêu cầu hasVerifiedScan(), owner/purpose và policy Conversation trước khi link message_attachment. Hiện chưa triển khai attachment Messaging; không coi hồ sơ K03.7 là evidence đã có gate attachment đó.

Việc giữ lifecycle avatar cũ là tương thích runtime non-message hiện hành, không phải xác nhận mọi file legacy an toàn. Rescan persisted của 8 file vẫn là việc vận hành tiếp theo, cần owner thực hiện; chưa được đánh dấu hoàn tất trong hồ sơ này.

## 3. Rescan qua owner

Đăng nhập đúng owner trong bảng trên ở frontend localhost:3000. Request dùng session cookie và CSRF hiện hành:

```http
POST http://localhost:8000/api/v1/files/5/complete
Accept: application/json
X-XSRF-TOKEN: <CSRF token của phiên owner>
Cookie: <session cookie do ứng dụng quản lý>
```

Body để trống. Không lưu cookie/token thực tế vào issue, log hoặc repository.

| Kết quả | Bước tiếp theo |
|---|---|
| 200 + clean + antivirus_scanned=true | Kiểm engine/version/time/hash trong database; giữ nguyên link hồ sơ |
| 403 file_forbidden | Kiểm user của session; file 5 cần User 47, Admin không tự có quyền complete thay owner |
| 503 scanner_unavailable / file_storage_unavailable | File pending; khắc phục nguyên nhân rồi retry, Retry-After 10 |
| 422 file_rejected | Kiểm nguyên nhân, xử lý qua flow thay file hiện hành; không ép lại clean |

## 4. Kiểm tra sau xử lý

```sql
SELECT id, owner_id, scan_status, scan_engine, scan_version, scanned_at,
       scanned_sha256 = checksum_sha256 AS hash_matches
FROM files
WHERE id IN (5,6,7,8,9,10,11,12)
ORDER BY id;
```

Một file được ghi nhận đã complete sạch khi scan_status=clean, scan_engine=clamav, scan_version/scanned_at có giá trị và hash_matches=true. Ghi riêng file pending/rejected/chưa xử lý; không suy ra cả tám đã rescan chỉ vì query clean thiếu evidence không còn trả dòng nào.

## 5. Giới hạn quét archive

ZIP/DOCX được kiểm giới hạn từng entry 25 MiB, tổng raw archive + dữ liệu entry 50 MiB, tối đa 1.000 entry; đọc stream thực tế và đối chiếu size/CRC. Archive mã hóa, hỏng, unsupported compression hoặc container nhúng thuộc các dạng guard nhận diện sẽ giữ pending thay vì được cấp clean. Chưa có kiểm tra đệ quy cho các container nhúng này; ghi rõ giới hạn khi review và khi hỗ trợ người dùng.

Preflight không phải antivirus; file vượt guard không được chuyển thành clean dù daemon có thể trả OK. Evidence phải phân biệt backend guard chặn với verdict do ClamAV phát ra. Kiểm MIME/magic bytes và guard không chứng nhận toàn bộ định dạng PDF/Office hoặc mọi container nhúng đều đã được phân tích đầy đủ.
