The persistent test launches separate PHP workers with independent PostgreSQL connections. The parent transaction locks the shared Program row; the test confirms each worker is blocked on that row with `pg_blocking_pids` before releasing it.

Assertions cover:
- Different payloads and keys racing at submission version 0 produce one 201 and one 409, with one version 1 row.
- Same key and payload racing at version 0 produce 201/200 with the same Submission ID and no duplicate row.
- Resubmit version 2 racing with review of version 1 produces one commit and one 409; the final Task/current Submission state matches the winner.

Each worker dispatches a prepared Laravel Request directly to TaskController. HTTP route/session middleware is covered by the separate sequential TaskWorkflowApiTest; this concurrency test isolates the transaction and row-lock behavior.
