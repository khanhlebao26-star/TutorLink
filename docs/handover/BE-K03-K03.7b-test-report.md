## 1. Kết quả và hành vi

Frontend, request upload và CompleteFile dùng giới hạn **5.000.000 byte/file**, kể cả avatar. Frontend kiểm cả service upload và form onboarding, hiển thị đúng 5 MB decimal. Backend kiểm số byte thực bằng UploadedFile::getSize(), không làm tròn qua rule max KiB. File rỗng hoặc quá lớn bị từ chối trước khi lưu object/FileRecord.

Complete dùng cùng cấu hình max_bytes và chỉ đọc tối đa giới hạn + 1 byte để nhận diện object quá lớn. Giữ kiểm actor/owner, purpose, private/local storage, extension, MIME/chữ ký, size thực, checksum, ZIP guard và hash object đọc lại. Không dùng client metadata làm bằng chứng hợp lệ.

| Trường hợp | Kết quả |
|---|---|
| File hợp lệ, không rỗng, size ≤ 5.000.000 byte | Upload 201/pending; complete 200/clean/complete=true |
| File upload rỗng hoặc quá giới hạn | 422 errors.file; không tạo object/FileRecord |
| Object tại complete vi phạm size/metadata/archive policy | 422 file_rejected; lưu rejected; không download như file hợp lệ |
| Storage không đọc được | 503 file_storage_unavailable; pending; không sử dụng được |
| Validation timeout/lỗi môi trường | 503 file_validation_unavailable; pending; có thể retry |

503 giữ Retry-After: 10. File mới complete trả antivirus_scanned=false, scanned_at=null; không có scanner tự động và không tạo evidence antivirus giả. Dữ liệu evidence thật từ trước vẫn theo policy K03.7a.

Purpose upload được hỗ trợ vẫn là avatar, verification_document, task_attachment, profile_document. Avatar nhận JPG/JPEG/PNG; tài liệu nhận PDF/JPG/JPEG/PNG/DOC/DOCX. Không mở upload chat hoặc tự triển khai Task/Submission/CV approval từ thay đổi giới hạn này.

## 3. API/schema delta

- Không thêm/bỏ endpoint; tổng operations vẫn 69. Không có migration hoặc schema delta.
- POST /api/v1/files mô tả file không rỗng và tối đa 5.000.000 byte cho mọi purpose đang hỗ trợ. Bỏ mô tả cũ 10.240 kilobytes; frontend không còn ngưỡng avatar 2 MiB/tài liệu 10 MiB.
- Mô tả nằm trong PHPDoc của rule file ở FileUploadRequest, được Scramble sinh ra; JSON không sửa bằng tay. Giữ request body, file và purpose bắt buộc cùng binary type.
- Complete/error DTO và antivirus_scanned/scanned_at không thay đổi so với K03.7a. Upload mới vẫn pending cho đến khi complete thành công.
- Giữ PHP upload_max_filesize=10M/post_max_size=12M làm trần nhận HTTP/multipart. Đây không phải giới hạn nghiệp vụ; backend vẫn từ chối file vượt 5.000.000 byte.

## 4. Legacy và dữ liệu test

Database local không có FileRecord vượt ngưỡng tại thời điểm kiểm kê, nên không cần backfill hoặc thay trạng thái/link. Không suy kết quả local thành kết quả staging/production: môi trường khác phải kiểm kê trước rollout, lập phương án cho file cũ vượt ngưỡng và không complete lại hàng loạt. Không xóa file đang được lịch sử tham chiếu. Giữ policy verification document, nullable scan-evidence columns và bằng chứng quét thực tế cũ; checksum hoặc complete không phải antivirus.

Lượt UI dùng tài khoản Tutor giả lập riêng, User ID 67; các fixture chuẩn bị 63–67 và file UI liên kết còn trong local như ghi tại báo cáo browser. 8 file API không liên kết của lượt cuối đã xóa qua API owner sau kiểm tra; không đụng tài khoản/file cá nhân có sẵn. ## 5. Known limitations và tiếp theo

- Chưa nghiệm thu K03.8: cần chặn chặt file_ids không hợp lệ, link/upload message và đối soát chat attachment legacy. Không mở attachment chat theo contract mới.
- File upload/complete của task_attachment/profile_document không chứng nhận quyền resource, workflow Task/Submission hoặc CV approval theo phiên bản đã triển khai.
- Test boundary dùng PNG/PDF fixture tổng hợp; không phải chứng nhận mọi cấu trúc PDF/Office hoặc malware. Không antivirus tự động; ZIP guard không phân tích đệ quy mọi container nhúng.
- Orphan cleanup/storage compensation, NFR throughput, lifecycle và realtime không được nghiệm thu bởi task này. File validation đồng bộ còn giữ User/File lock theo K03.7a.
- Redocly còn 43 warnings; middleware File legacy có thể trả 403 message-only. Không tuyên bố lint hết warnings hoặc mọi error envelope đã thống nhất.
- Browser evidence được copy từ outputs sang thư mục được Git theo dõi; ảnh failure của các lượt chuẩn bị không đưa vào bộ bàn giao. Báo cáo browser gốc vẫn phản ánh thời điểm trước các kiểm tra bàn giao bổ sung tại đây.

Tiếp theo: K03.8. Không có blocker K03.7b trong các kiểm tra đã chạy; chờ Hoàng review, chưa đánh dấu toàn BE-K03 hoàn tất.
