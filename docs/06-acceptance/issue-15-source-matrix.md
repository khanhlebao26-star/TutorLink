## API status and compatibility notes

`GET /catalog/categories` is the existing catalog source; the live check reported by the coordinator returned 200 with one category. The coordinator reports that the probed Listing, Tutor, and availability endpoints returned 404. The OpenAPI entries for `/listings`, `/listings/{slug}`, and `/me/listings` explicitly say they are planned for W1-A3 and are not implemented in the phase-2 runtime. Their current OpenAPI query/request/response shape is narrower than the B3 proposal. Public Tutor, reviews, and availability endpoints are proposal-only and are not listed in OpenAPI. Current project status likewise says Marketplace Listing API is absent and no Review API is present.

For availability, the proposal specifies ISO weekdays 1–7 (Monday–Sunday), IANA timezone, `HH:mm`, same-day start < end, adjacent slots allowed, and overlaps rejected. The server must validate and return 422 field errors. The shared proposal error set includes 409 conflict, and the current UI preserves the draft and refetches the latest schedule on 409; the precise version/conflict contract remains unresolved for A3. No endpoint success is claimed.

The B3 proposal’s `DELETE /me/listings/{id}` means terminal archive that preserves Program references. OpenAPI currently calls the operation “Delete a draft listing,” promises `204 Listing deleted`, and returns `409` if the listing is active or referenced. This is an unresolved semantic conflict, not acceptance of archive behavior. Keep archive controls behind returned `allowed_actions` and A3’s confirmed contract.
